# IPRM - Інститут Плазмотерапії та Регенеративної Медицини

Веб-сайт Інституту Плазмотерапії та Регенеративної Медицини. Інформаційний портал з каталогом курсів, системою авторизації та обліковими записами користувачів.

## Технології

- **Backend:** Flask 3.0+, SQLAlchemy ORM, Flask-Login, Flask-WTF, Flask-Migrate, Flask-Limiter
- **Frontend:** Jinja2, власна CSS-дизайн-система (токени й компоненти в `common.css`, посторінкові `page-*.css`; каталог -- `/admin/design-system`), Canvas API. Tailwind **не використовується**
- **База даних:** SQLite (dev), PostgreSQL (prod, через pg8000), Alembic-міграції
- **Деплой:** GitHub Actions, rsync на VPS, systemd + gunicorn
- **Безпека:** CSRF, rate limiting, security headers, admin-декоратор
- **Мови інтерфейсу:** Українська (базова), російська та англійська через Flask-Babel (впроваджується, див. [docs/i18n.md](docs/i18n.md))

| Резервні копії БД (`/admin/backups`) | `pg_dump --format=custom` у `BACKUP_STORAGE_PATH` (дефолт `backups/`, виключено з rsync і з git), SHA-256 на кожну копію. Автоматично: повна копія щодня о 3:00, очищення о 4:00, звірка контрольних сум усіх копій + лист-звіт адмінам щотижня в неділю о 5:00, і **повна копія перед кожним деплоєм** -- до `flask db upgrade`, щоб була точка повернення з-під невдалої міграції (збій копії зупиняє деплой; обхід -- [deploy/README.md](deploy/README.md#копія-бд-перед-кожним-деплоєм)). Вручну: сторінка (створення, перевірка однієї копії чи всіх, завантаження, видалення, очищення) і CLI-група `flask backup`. **Відновлення лише через CLI** -- `pg_restore --clean` проти робочої бази, поки gunicorn тримає з'єднання, або падає на блокуваннях, або зносить таблиці посеред роботи сайту, тому кнопки в адмінці для нього немає; без запобіжної копії воно й у CLI не починається (обхід -- `--force`). Retention має підлогу: `BACKUP_MIN_KEEP` (3) найсвіжіших копій лишаються попри `BACKUP_RETENTION_DAYS` (30), інакше місяць без бекапів означав нуль копій. Система **не має права ламатись молча**, тож сторінка піднімає тривогу про відсутню/застарілу копію (`BACKUP_MAX_AGE_HOURS`), брак місця (`BACKUP_DISK_FREE_MIN_PERCENT`) і відсутність `postgresql-client`. Сервер мусить мати `postgresql-client` не нижче за версію БД -- [deploy/README.md](deploy/README.md#postgresql-client-резервне-копіювання) |
