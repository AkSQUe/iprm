# Мультимовність (i18n)

Сайт перекладається трьома мовами через Flask-Babel:

| Код | Мова | Роль |
|-----|------|------|
| `uk` | Українська | Вихідна мова коду і шаблонів (без каталогу перекладів) |
| `ru` | Російська | Каталог `app/translations/ru/` |
| `en` | Англійська | Каталог `app/translations/en/` |

## Архітектура

- `app/extensions.py` -- інстанс `babel = Babel()`, ініціалізація у `create_app()`.
- `app/i18n.py` -- `get_locale()`: пріоритет `g.lang_code` (URL-префікс, Фаза 1)
  -> `session['lang']` -> `Accept-Language` -> `uk`.
- `config.py` -- `LANGUAGES`, `BABEL_DEFAULT_LOCALE`, `BABEL_DEFAULT_TIMEZONE`,
  `BABEL_TRANSLATION_DIRECTORIES`.
- `babel.cfg` -- конфіг екстракції рядків (Python + Jinja2-шаблони).
- `app/translations/` -- каталоги `.po` (у git) і `.mo` (генеруються, у .gitignore).

## Правила маркування рядків

- Шаблони Jinja2: `{{ _('Текст') }}`; множина -- `ngettext`.
- Python (роути, flash, сервіси): `from flask_babel import gettext as _`.
- Рядки, що обчислюються при імпорті модуля (WTForms labels, константи,
  `Specializations`): `from flask_babel import lazy_gettext as _l` --
  екстрактор налаштований і на `_l`.
- Фонові рендери (листи зі scheduler): обгортати рендер у
  `flask_babel.force_locale(user.preferred_language or 'uk')` -- поза
  запитом селектор локалі повертає дефолт.
- Msgid -- завжди українською (вихідна мова), без HTML усередині, де можливо.

## Робочий цикл перекладу

Після додавання/зміни `_()`-рядків у коді чи шаблонах:

```bash
# 1. Витягти рядки в POT-шаблон (генерується, не в git).
# ВАЖЛИВО: вхідна тека -- app (НЕ корінь: на node_modules pybabel
# у Windows падає; шляхи в babel.cfg відносні до app/).
pybabel extract -F babel.cfg -k _l -o app/translations/messages.pot --project=IPRM --no-location app

# 2. Влити нові рядки в наявні каталоги ru/en (зберігає готові переклади)
pybabel update -i app/translations/messages.pot -d app/translations

# 3. Переклад: заповнити msgstr у app/translations/{ru,en}/LC_MESSAGES/messages.po

# 4. Локальна перевірка: скомпілювати і перезапустити застосунок
pybabel compile -d app/translations
```

Якщо `pybabel` не в PATH (Windows): `python -m babel.messages.frontend <команда ...>`.

Команда `init` потрібна лише для нової мови:
`pybabel init -i app/translations/messages.pot -d app/translations -l <код>`.

## Деплой

`.mo`-файли НЕ комітяться: у `deploy.yml` після `pip install` виконується
`pybabel compile -d app/translations` на VPS (перед `flask db upgrade` і
рестартом). Тому в git достатньо актуальних `.po`.

Увага: неперекладені msgstr -- це не помилка (показується українська),
але позначені `#, fuzzy` записи pybabel НЕ компілює -- прибирайте fuzzy-мітку
після вичитки перекладу.

## Переклади JSON-полів: ключ = хеш джерела

Переклад JSON-поля (`faq`, регалії тренера, блоки блогу, `items`) зберігається
в `translations` не копією структури, а плоскою мапою `{ключ: текст}`, яка
накладається на поточну українську структуру при читанні
(`app.i18n.apply_json_overrides`).

**Ключ -- це `source_key(укр_текст)`**, тобто `sha1[:12]` від оригіналу.
Переклад прив'язаний до ТЕКСТУ, тому перестановка, вставка чи видалення
елемента структури його не збивають; зникло джерело -- фолбек на українську.

До міграції `i18n_srckey_20260731` ключем був крапко-роздільний ШЛЯХ
(`0.data.html`). Саме він і ламався: вставили новий блок на початок -- шлях
лишався валідним, і готовий переклад мовчки з'їжджав на сусідній елемент.
Читання legacy-ключів збережено як запобіжник для даних, які не пройшли
міграцію; запис завжди у новому форматі.

Перелік того, ЩО саме перекладається, живе в
`app/services/translation_registry.py` (`TranslationUnit`, `units()`,
`apply_units()`, `coverage()`) -- одне джерело правди для адмін-редактора,
інлайн-вкладок і майбутнього xlsx-каналу. `uid` одиниці (`title`,
`faq:9c1f2a3b4d5e`) стабільний і придатний як ключ у зовнішніх файлах.
Покриття рахується по одиницях, а не по полях: інакше FAQ з одним
перекладеним питанням із шістнадцяти рахувався б виконаним.

## Плюралізація

Числівники на публічних сторінках -- фільтр `plural(n, 'ключ')`
(`app/i18n_plurals.py`): централізований словник форм per-locale
(bpr_points, seats, years тощо), правило -- слов'янське (3 форми: one/few/
many) для uk/ru, просте (2) для en. Обрано замість gettext-`ngettext`, бо
мова-джерело (укр) з 3 формами вимагала б окремого uk-каталогу. Нові
іменники додавати в `PLURAL_FORMS`. Фільтр `uk_plural` лишається лише для
uk-only PDF-сертифікатів.
