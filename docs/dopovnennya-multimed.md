# Додатковий контент з прототипу Multimed → для plasma-regen.com

**Джерело:** https://asset-manager--barashdm.replit.app/index.html (прототип «Multimed Beauty Education»)
**Дата:** 08.07.2026

## Контекст

Це маркетинговий прототип того ж бізнесу: ті самі тренери (Чіркова, Школьний, Рубан, Бондар, Шевчук, Гусак), ті самі курси (PRP/PRF, плазмотерапія в трихології тощо), тренери лінкуються на `multimed.ua`, у футері — зв'язок з `mm-medic.com`. Фактично це готовий референс UI/контенту, з якого можна брати цілі блоки для plasma-regen.

**Важливо:** сайт сам себе називає прототипом. Статуси й цифри — плейсхолдери, які «потрібно підтвердити перед запуском» (ISO 13485, бали БПР/IPRM, логотипи партнерів, відгуки). Тобто структуру беремо, а конкретні дані — тільки після підтвердження.

## Частина 1. Що прямо закриває пункти нашого плану

### → Блок 1.1 Розширені картки курсів
Multimed має саме той формат картки, який просив Дмитро. На картці одразу: **ціна** («від 24 900 ₴» / фіксована «6 500 ₴»), **дата старту**, **тренер (фото + ім'я)**, **бейджі формату** (Офлайн / Онлайн / Гібрид), **механіка** (Ін'єкції / Апаратна / Догляд / Бізнес / PRP-PRF), **рівень** (LEVEL 1/3, 2/4…), **статус-бейдж** (Хіт / Новий / Рекомендуємо / Популярне / Для старту), **лічильник місць** («4 місця»).
→ Готовий шаблон картки — можна взяти як референс верстки й набору полів. Формат ціни «від N ₴» вирішує наш нюанс з різними інстансами (Блок 1.1).

### → Блок 1.3 Лічильник вільних місць
Реалізовано на кожній картці й у календарі («3 місця», «малі групи»). Референс формулювання є.

### → Блок 1.4 Бали БПР як опція
У блоці «Довіра» бали БПР/IPRM винесені як окремий підтверджуваний статус, а не жорстко на кожній картці — збігається з нашим правилом «бейдж лише коли балів > 0».

### → Блок 3.2 Швидкі фільтри за спеціальністю
Найсильніша частина. Повноцінна панель фільтрів каталогу: пошук + випадайки **Напрям / Спеціальність / Формат / Механіка / Тривалість / Бюджет** + сортування (популярні / нові / ціна ↑↓) + чіпси «Усі / Популярні / Нові / Рекомендуємо / Скинути» + бігучий рядок спеціальностей (Косметологія · Дерматологія · Трихологія · Гінекологія · Стоматологія · Ортопедія · Регенеративна медицина).
→ Це саме та «бігуча строка з чіпсів спеціальностей», яку описував Дмитро. Готовий референс.

### → Блок 2.4 Інтерактивні відгуки
Блок відгуків із зірковим рейтингом і підписом «Ім'я · місто · спеціальність». Формат клікабельних/довірливих відгуків збігається з нашою ідеєю (посилання на сторінку лікаря додаємо ми).

### → Блок 2.5 «Наступний крок / схожі курси»
Реалізовано глибше — як **«Карта прогресу»**: маршрути навчання (естетист / ін'єкційний лікар / плазмотерапія за спеціальностями) зі станціями LEVEL 1→2→3. Це апгрейд ідеї «схожі курси» до навчальних треків.

### → Блок 2.2 Тарифна вилка
Маршрути йдуть у зв'язці з **пакетними знижками** («3 рівні · пакет −15% / −18% / −20%»). Це готова механіка «вилки пропозицій», яку хотів Дмитро: базовий курс + догрузка + пакетна ціна.

### → Блок 5.1 B2B-блок
Готовий блок **«Для команд і клінік»**: 20% знижки для груп від 3 фахівців, формат онлайн/офлайн/гібрид, окрема форма (Ім'я, Прізвище, Телефон, Email, кількість фахівців 3–5 / 6–10 / 10+). → Можна брати майже as-is, коли буде контент.

### → Блок 5.2 Плашка з подіями / календар
Є **топ-бар** «Найближчі події: 15 липня · PRP/PRF» + повний **календар подій**, де кожна подія має окремий anchor «для реклами, email або SMS» (перегукується з UTM/трекінгом, Блок 5.3). Це кращий варіант за поточний pop-up.

### → Блок 4 Скорочення шляху до оплати
Замість форсованої повної реєстрації Multimed веде на **консультацію / лід-форму** (мінімум полів: Ім'я, Прізвище, Телефон, Email + що хоче опанувати). Збігається з ідеєю Дмитра «зібрати мінімум, решту запитати пізніше».

## Частина 2. Нові ідеї, яких немає в поточному плані

1. **Калькулятор окупності (ROI).** Інтерактив: чек процедури × записи × вартість курсу → «Дохід на місяць» і «Окупність ≈ N записів». Сильний продажний інструмент для медичної аудиторії, орієнтований на дохід лікаря. На plasma-regen немає нічого подібного. Рекомендую до впровадження.

2. **Орієнтир окупності на картці/герої.** Мікро-підказки типу «Орієнтир окупності 3–4 записи за чека 6 000–9 000 ₴». Дешево додати, підсилює рішення.

3. **Рівні складності курсів (LEVEL 1/3, 2/4).** Явна градація складності — допомагає лікарю обрати за досвідом. Можна ввести як атрибут курсу.

4. **Маршрути/треки навчання** (див. вище) як окрема сутність — не просто «схожі курси», а керований шлях зі знижкою за пакет.

5. **Блок «Як це працює»** — 4 кроки (обери напрям → навчання → практика → впровадження). Знижує тривогу перед покупкою.

6. **Перемикач мов UA/EN.** На plasma-regen зараз немає — може бути актуально для ширшої аудиторії.

7. **Cookie-згода з аналітикою лише за згодою** («Аналітику вмикаємо лише за згодою»). Правильний підхід до GA4-consent (перегукується з нашою темою трекінгу).

8. **Блок «Флагманський напрям»** — пояснення PRP/PRF/PPP як системи (підготовка → центрифугування → клінічний протокол). Освітній контент, що піднімає експертність.

## Частина 3. Готовий контент, який можна перенести напряму

- **Тренери** — ті самі люди, що на plasma-regen: фото + короткі регалії + лінк на повний профіль. Можна вирівняти подачу.
- **Тексти-описи курсів** (короткі «продажні» підзаголовки під кожен курс) — краще написані, ніж голі назви на поточному сайті.
- **Структура події в календарі** (дата, напрям, тренер, місць, вартість, кнопка).
- **Форми лід-генерації** (консультація + B2B) — готова структура полів.

## Ризики / що не копіювати без перевірки

- Статуси **ISO 13485, бали БПР/IPRM, логотипи партнерів** — у прототипі це плейсхолдери. Переносити лише з підтвердженими даними.
- **Відгуки** (Олена·Київ, Марина·Львів) — приклади-заглушки. Ставити лише реальні (узгоджується з нашим рішенням у Блоці 2.4).
- **Ціни й дати** на Multimed відрізняються від plasma-regen (напр. базова плазмотерапія 6 500 ₴ проти 6 000 ₴). Не змішувати дані — джерело істини по цінах у нас.
- Це домен на replit.app (прототип), не прод — брати як референс дизайну/структури, а не як джерело живих даних.
