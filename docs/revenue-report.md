# Виручка й зобов'язання

Сторінка `/admin/revenue` (право `revenue.view`, файл -- `revenue.export`)
показує за київський місяць, які оплати вже стали виручкою, а які ще є
нашим боргом перед учасниками.

## Правила

Погоджено 08.10.2026. Код -- `app/services/finance_report.py`, тести --
`tests/test_services/test_finance_report.py`.

| Що | Правило |
|---|---|
| Захід виконано | настала дата завершення заходу (`end_date`, без неї -- `start_date`). Присутність учасника не важлива: після заходу повернення за Політикою немає |
| Онлайн-курс виконано | видано доступ (`provisioned_at`) -- цифровий продукт |
| Місяць виручки | місяць виконання, а не оплати. Оплата з вересня за захід 17.10 -- зобов'язання на кінець вересня і виручка жовтня |
| Зобов'язання | оплата надійшла до межі звіту, а виконання ще попереду (або в заходу немає дат, або доступ не видано) |
| Сума | `payment_amount - refunded_amount`. Повністю повернені й безкоштовні не рахуються |
| Оплата без дати | у звіт не йде, а показується окремим попередженням: без `paid_at` її не віднести до місяця |
| Межі місяця | київські. Для поточного місяця межа звіту -- "зараз" |
| Відмова учасника | статус «скасовано» або задоволена заявка на повернення за Політикою (не `transfer_diff` -- різниця тарифу при перенесенні). Погоджено 10.10.2026 |
| Заявка чекає рішення | уся сума -- зобов'язання, навіть якщо захід уже відбувся |
| Відмова з поверненням | утримане (`payment_amount - refunded_amount`) -- виручка на дату повернення (`refunded_at`), а не заходу: закритий після звірки місяць уже не змінюється |
| Відмова без повернення | виручка на дату скасування (`cancelled_at`, ставиться моделлю на кожен перехід у «скасовано») |

## Що варто знати

* Дату виконання рахує одна функція -- `finance_report.fulfilled_at`. Її ж
  API віддає mm-medic (`fulfilled_at` у реєстраціях і покупках), тож блок
  «Зобов'язання за навчанням» там і цей звіт сходяться.
* Відмови показано окремими рядками («відмова учасника») з датою
  повернення чи скасування.
* `cancelled_at` для скасованих до 10.10.2026 наповнено міграцією
  найкращою відомою датою: повне повернення, рішення за заявкою, інакше
  остання правка рядка (для скасованих вручну -- верхня межа).

* Звіт за минулий місяць може змінитися заднім числом: оплата, що
  прийшла після заходу, додається до виручки місяця заходу.
* Повернення враховуються на сьогодні, а не на кінець місяця звіту.
* Роль `viewer` права `revenue.view` за замовчуванням не отримує, хоча
  бачить решту розділу "Продажі". `flask rbac sync` нове право створює, але
  наявним ролям не видає: його вмикають у матриці `/admin/access`.
* Сторінка показує підсумки за заходами й курсами; окремі оплати з
  учасниками -- в xlsx (аркуші "Виручка" і "Зобов'язання", суми збігаються
  з картками на сторінці).
