# Дизайн: SEO публічних сторінок

Дата: 2026-08-29
Статус: затверджено до планування

## Контекст

Базовий SEO-шар проєкту вже зрілий. `base.html` віддає title, meta
description, OG, Twitter card, canonical, hreflang-альтернативи та
`EducationalOrganization` JSON-LD. `sitemap_service.py` будує по одному URL
на мову з `xhtml:link`-альтернативами та `x-default`. `robots.txt` закриває
приватні розділи разом з їхніми мовними дзеркалами, а `X-Robots-Tag`
проставлений на admin, auth, payments, quiz, registration.

Ця робота НЕ переписує той шар. Вона закриває чотири речі, яких у ньому
бракує: структуровані дані там, де їх немає; дублювання розмітки хлібних
крихт; відсутність будь-яких сторожів, що не дають SEO-боргу повернутись;
і кілька точкових дефектів.

## Що вже правильно і НЕ чіпається

Ці пункти перевірено. Плану не можна витрачати на них жодної задачі.

* `_hreflang_alternates()` і `localized_urls()` (`app/i18n.py`) коректні,
  включно з `x-default`; sitemap перевикористовує ту саму функцію.
* Юридичні сторінки нелокалізовані свідомо -- відсутність hreflang на них
  не дефект.
* Кожен `<img>` на публічних шаблонах уже має `alt`. Порожніх немає.
* Відсутній `loading=` на логотипах у `header.html`/`footer.html` --
  свідомо: вони above-fold.
* `Course`, `CourseInstance`, `Offer`, `FAQPage`, `Person`, `BlogPosting`
  вже існують і побудовані правильним патерном (dict + `|tojson`).

## Поза межами цього циклу

* Клініки. Модель `Clinic` не має адреси, міста, телефону чи гео, а
  адмін-CRUD для клінік не існує взагалі -- жоден шлях у коді не створює
  рядок `clinics`. `MedicalClinic` без адреси не дає нічого в локальній
  видачі, тому ця гілка виноситься в окремий брейншторм як CMS-фіча.
* Ключові слова, контент і позиції. Semrush MCP не має юнітів; гілка
  "дані спершу" відкладена.
* Рейтинг рівня організації. Google його не показує; найслабше твердження
  на сайті не варте розмітки.

## Глобальні обмеження

1. **Кожен JSON-LD будується як Jinja-dict і віддається через `|tojson`.**
   Літеральний JSON у шаблоні заборонений. Саме це робить валідність
   перевірюваною тестом, а не оком рецензента.
2. **Усі URL у структурованих даних абсолютні.** Відносний шлях у
   `image`, `logo`, `item`, `url` -- дефект.
3. **Структуровані дані описують лише те, що реально є на сторінці.**
   Розмітка, згенерована з даних, яких користувач не бачить, або з
   демо-заглушки, заборонена без винятків.
4. Компонент оголошується один раз. Той самий критерій, що діє для CSS у
   `CLAUDE.md`: правка мусить впливати на всі сторінки-споживачі.
5. Без emoji, без inline-коду, коментарі українською -- як у решті репо.
6. Автоматичних комітів немає. Коміт робить людина.

## Секція 1: Спільний шар структурованих даних

Створюється `app/templates/partials/schema/` з макросами:

| Що | Де оголошується | Що замінює |
| --- | --- | --- |
| макрос `breadcrumbs(items)` | `partials/schema/_breadcrumbs.html` | 9 копій `BreadcrumbList` |
| Jinja-глобал `abs_url(path)` | Python, поряд з рештою глобалів застосунку | розсіяний `request.url_root.rstrip('/') ~ path` |

`abs_url` -- саме глобал, а не макрос: його результат підставляється
значенням у dict (`'image': abs_url(course.card_src)`), а макрос повертає
Markup із пробілами і для цього не годиться. Порожній чи None-шлях
повертає None, щоб виклик можна було лишати без зовнішнього `{% if %}`.

Макрос `breadcrumbs` віддає ГОТОВИЙ тег `<script type="application/ld+json">`
разом із вмістом -- сторінка його лише викликає.

`breadcrumbs(items)` приймає список `(name, url)`; в останнього елемента
`url` порожній -- поточна сторінка не має `item` за специфікацією
schema.org. Макрос сам додає кореневий елемент "ІПРМ".

Дев'ять файлів-споживачів, які переводяться на макрос:

```
clinics/detail.html   clinics/list.html
courses/detail.html   courses/list.html
online/detail.html    online/list.html
trainers/detail.html  trainers/list.html
main/bpr_documents.html
```

Міграція мусить бути вихід-нейтральною: тест із секції 4 пишеться і
запускається ДО неї, і той самий набір тверджень має проходити після.

## Секція 2: Прогалини покриття

Одна пачка дрібних незалежних правок:

| Файл | Правка |
| --- | --- |
| `blog/list.html` | `Blog` + хлібні крихти |
| `main/index.html` (лабораторії) | хлібні крихти |
| `main/offer.html`, `privacy.html`, `refund.html`, `disclaimer.html`, `cookies.html` | хлібні крихти |
| `main/index.html` (лабораторії) | власний `<title>`: зараз дослівно дублює головну |
| `courses/detail.html`, `online/detail.html` | абсолютні URL у JSON-LD `image` |
| `courses/detail.html` | `instructor.name` через `.t('full_name')` |

Дефект з `image`: `og_image` абсолютизує `course.card_src` через
`request.url_root`, а `course_schema` кладе той самий шлях відносним
(`MediaFile.variant_url` повертає `/media/...`).

Дефект з `title`: `main/home.html` і `main/index.html` мають дослівно
однаковий `<title>`. Головна лишає свій; сторінка лабораторій дістає
власний, що описує саме лабораторії.

Перевірено і НЕ є дефектами, попри те що показує побіжний grep:
п'ять `<h1>` в `main/unsubscribe.html` лежать у взаємовиключних гілках
`{% if %}` -- рендериться рівно один; два `<img>` у `main/contact.html` --
іконки 20x20 з явними розмірами, `loading="lazy"` на них нічого не дає.

## Секція 3: Рейтинги лише з реальних даних

`AggregateRating` і вузли `Review` на сторінках курсу та онлайн-курсу,
побудовані з опублікованих рядків `Review`, прив'язаних саме до цього
курсу (`course_id` / `online_course_id`).

Жорстке правило: якщо прив'язаних опублікованих відгуків нема -- у
структуровані дані не йде НІЧОГО. Гілка з демо-цитатами в
`main/home.html:388` не породжує розмітки за жодних умов. Тест мусить
доводити обидві поведінки: є відгуки -> є `AggregateRating` з
`ratingValue`/`reviewCount`, що збігаються з рядками БД; нема -> ключа
`aggregateRating` у JSON немає.

## Секція 4: Сторожі -- `tests/test_seo/`

Пишеться ПЕРШИМ, до секцій 1-3.

Публічні маршрути виводяться з `app.url_map`: беруться `GET`-ендпоінти без
обов'язкових параметрів, крім блюпринтів admin, auth, payments, quiz,
registration і сервісних (`static`, `robots`, `sitemap`). Динамічні
сторінки (курс, тренер, клініка, стаття) покриваються окремо через
фікстури на зразок `tests/test_routes/test_sitemap.py`.

Твердження на кожен публічний маршрут:

* рівно один `<h1>`;
* `canonical` присутній, абсолютний, без query-рядка;
* meta description непорожній;
* кожен блок `application/ld+json` парситься `json.loads` і має
  `@context` та `@type`;
* жодного відносного URL у полях `image`, `logo`, `item`, `url`;
* набір `hreflang` дорівнює `LANGUAGES` плюс `x-default` -- для
  локалізованих ендпоінтів, і порожній для нелокалізованих.

Окремо, поперек усіх публічних маршрутів: `title` і meta description
унікальні.

Довжини: цільові межі -- title 30-60, description 120-160. Спершу
заміряти поточні значення. Сторінки, що виходять за межі, виправляються в
секції 2. Якщо якусь не можна виправити без рішення про контент, вона
заноситься в іменовану константу-виняток у тесті з коментарем, ЧОМУ, а не
пом'якшенням загальної межі.

Приватні маршрути перевіряються дзеркально: `noindex` присутній.
