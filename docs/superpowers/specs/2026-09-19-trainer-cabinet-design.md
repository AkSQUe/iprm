# Кабінет тренера: роль, анкета, договір, часті питання

Дата: 2026-09-19. Статус: реалізовано 19.09.2026 (не запушено), міграція
чекає деплою.

## Мета

Тренер (викладач ІПРМ) входить на сайт своїм акаунтом і має власну
сторінку: найближчі заходи з числами реєстрацій та три дочірні сторінки --
«Анкета тренера», «Договір», «Часті питання». Анкета замінює docx-анкету,
яку зараз заповнюють вручну і надсилають у телеграм.

## Ухвалені рішення

| Питання | Рішення |
| --- | --- |
| Що таке «роль тренера» | Прив'язка картки `Trainer` до акаунта `User` (`Trainer.user_id`). НЕ RBAC-роль: будь-яка RBAC-роль робить `is_staff` істиною і відкриває адмінку. |
| Структура анкети | Один профіль на тренера + кілька пропозицій курсу/доповіді. |
| Синхронізація з публічною карткою | Немає. Анкета -- службові дані для куратора; публічну картку редагує контент-редактор, як і зараз. |
| Що видно про реєстрації | Лише числа, без персональних даних учасників. |
| Договір і FAQ | Редагуються в адмінці (`SiteSettings`). |
| Email для договорів | Порожній до заповнення в адмінці; до того -- загальний `SiteSettings.email`. |
| Редагування пропозиції після надсилання | Заблоковано, доки куратор не поверне на доопрацювання. |

## 1. Дані

Одна alembic-ревізія (id <= 32 символів).

### `trainers.user_id`

`BigInteger`, FK `users.id` `ondelete='SET NULL'`, nullable, unique.
Relationship `Trainer.user` / `User.trainer_card` (uselist=False).

Тренер -- користувач, у якого є прив'язана картка з `is_active=True`.

### `trainer_profiles` (1:1 з `trainers`)

| Блок | Поля |
| --- | --- |
| Контакти | `full_name`, `birth_date` (Date), `education` (Text), `position_titles` (Text, посада та регалії), `workplace` (Text, з містом), `phone`, `email`, `social_links` (Text) |
| Фото | `photo_media_id` (FK `media_files`, SET NULL) АБО `photo_url` (String 500) |
| ФОП | `fop_recipient`, `fop_iban`*, `fop_rnokpp`*, `fop_payment_purpose` (Text, згідно КВЕД), `card_number`* |
| Договір | `tax_id`*, `registration_address` (Text), `edrpou` |
| Службові | `trainer_id` (FK, unique, CASCADE), `created_at`, `updated_at` |

`*` -- шифруються Fernet (ключ з `SECRET_KEY`, як `_get_fernet` у
`app/models/site_settings.py`). У колонці лежить шифротекст; доступ -- через
властивості-обгортки на моделі. Спільний хелпер шифрування виноситься з
`site_settings.py`, щоб не дублювати.

«Заповненість» профілю -- властивість `is_complete`: заповнені ПІБ, телефон,
email, IBAN, РНОКПП, ідентифікаційний код, адреса.

### `trainer_course_proposals` (N:1 до `trainers`)

| Поле | Тип / обмеження |
| --- | --- |
| `title` | String(50), обов'язкове |
| `theses` | JSON-список рядків, 1..10 (анкета рекомендує 5-10) |
| `language` | String(50) |
| `relevance` | Text (актуальність) |
| `target_specialties` | Text |
| `resources` | Text (цікаві статті/ресурси) |
| `future_topics` | Text |
| `quiz_url` | String(500), nullable (Google-форма тестування) |
| `status` | `draft` / `submitted` / `accepted`, CHECK-констрейнт |
| `curator_comment` | Text, nullable |
| `submitted_at`, `created_at`, `updated_at` | DateTime tz |

Переходи: `draft -> submitted` (тренер), `submitted -> accepted` (куратор),
`submitted -> draft` з коментарем (куратор, «повернути»). Тренер редагує і
видаляє лише `draft`.

### `site_settings`

- `trainer_contract_media_id` -- FK `media_files` (PDF договору), SET NULL.
- `trainer_faq_html` -- Text; значення за замовчуванням у міграції --
  погоджений текст FAQ з плейсхолдером `{email}`.
- `trainer_contract_email` -- String(255), nullable.

`MediaFile.USAGE_TYPES` / `USAGE_LABELS` / `ENTITY_LABELS` доповнюються
типами для договору (`document` / `site_settings`) і фото анкети.

## 2. Доступ

Декоратор `trainer_required` (`app/trainer/decorators.py`):
- анонім -> редирект на вхід (як `login_required`);
- користувач без активної прив'язаної картки -> 404;
- інакше кладе картку в `g.trainer`.

Кожен запит до пропозиції фільтрується за `trainer_id == g.trainer.id`;
чужа пропозиція -> 404.

## 3. Сервіс (`app/services/trainer_cabinet.py`)

- `upcoming_instances(trainer)` -- `CourseInstance`, де тренер серед
  `effective_trainers`: призначений на дату, АБО призначений на курс і в
  дати немає власних тренерів. Статус `published`/`active`,
  `start_date IS NULL OR start_date >= now` (той самий предикат, що в
  `services/course_listing.py`). Сортування за датою.
- `registration_counts(instance_ids)` -- ОДИН агрегатний запит,
  `{instance_id: {total, paid, offline, online}}`; `cancelled` не
  рахується.
- `trainer_courses(trainer)` -- курси, де тренер призначений.
- Операції над пропозиціями: `submit`, `accept`, `return_to_draft`, з
  перевіркою допустимих переходів (невалідний -> виняток, маршрут -> 409/flash).

## 4. Кабінет (блюпринт `trainer`, `LocalizedBlueprint`, `/trainer`)

| Маршрут | Призначення |
| --- | --- |
| `GET /trainer/` | Кнопки на дочірні сторінки (бейдж на анкеті, якщо `not is_complete`); найближчі заходи: дата/час, курс, місто або «онлайн», зареєстровано / оплачено / очно / онлайн / місць усього, посилання на публічну сторінку; «Мої курси». |
| `GET, POST /trainer/profile` | Форма профілю: три блоки як у docx; фото файлом (лише зображення, через `media_service`) або посиланням. Нижче -- список пропозицій. |
| `GET, POST /trainer/proposals/new` | Нова пропозиція (чернетка). |
| `GET, POST /trainer/proposals/<id>` | Редагування чернетки; для `submitted`/`accepted` -- перегляд. Показує коментар куратора. |
| `POST /trainer/proposals/<id>/submit` | Надіслати куратору. |
| `POST /trainer/proposals/<id>/delete` | Видалити чернетку. |
| `GET /trainer/contract` | Інструкція + кнопка завантаження; без файлу -- «буде додано найближчим часом». |
| `GET /trainer/contract/download` | `send_file` PDF лише тренерам; 404 без файлу. |
| `GET /trainer/faq` | `sanitize_rich_text(trainer_faq_html)` з підстановкою `{email}` (email для договорів або `SiteSettings.email`). |

Тези -- динамічний список з кнопкою «+ теза» (окремий JS-файл);
без JS -- textarea, одна теза на рядок. Під полями пропозиції -- підказки
з анкети («лікарю важливо це знати, тому що...» тощо).

Навігація: у `templates/partials/header.html` пункт «Кабінет тренера» для
користувача з активною карткою, поряд з «Особистим кабінетом».

i18n: інтерфейс -- `_()` / `_l`; текст FAQ з адмінки -- лише український.

## 5. Адмінка

Права -- наявний модуль RBAC `trainers`; нових дій немає.

- Форма тренера: поле «Акаунт на сайті» (email; помилка, якщо акаунта
  немає або він уже прив'язаний до іншого тренера).
- Вкладка «Анкета» у картці тренера: профіль лише для читання; зашифровані
  поля відкриті лише з `trainers.manage`, інакше маскуються (`•••• 1234`).
- Пропозиції курсу в картці тренера: «Прийнято», «Повернути на
  доопрацювання» (з коментарем).
- Список тренерів: індикатори «акаунт прив'язано», «анкету заповнено»,
  «нових пропозицій: N» (агрегатом, без N+1).
- Налаштування сайту, блок «Для тренерів» (право `settings`): завантаження
  PDF договору (лише `application/pdf`), редактор FAQ, email для договорів.

## 6. Сповіщення

При `draft -> submitted` -- лист через `email_service` на email для
договорів (fallback -- `SiteSettings.email`): назва курсу, тренер,
посилання в адмінку. Листів тренеру про «прийнято/повернуто» немає.

## 7. Стилі

- Компоненти (кнопки, форми, поля, бейджі, картки, порожні стани) -- з
  дизайн-системи; сторінкові `page-trainer-*.css` -- лише layout.
- Новий компонент (напр. рядок заходу з лічильниками), якщо знадобиться,
  -- у компонентний CSS і в каталог `/admin/design-system`.
- Без inline-стилів і скриптів.
- Перевірка: `layer_check.py`, `shadowed_rules.py`,
  `pytest tests/test_design_system/`.

## 8. Тести (`tests/test_trainer_cabinet/`)

- Доступ: анонім -> вхід; без картки -> 404; неактивна картка -> 404;
  тренер -> 200; staff без картки -> 404.
- Відбір заходів: тренер на даті; тренер на курсі, дата без тренерів; дата
  з іншими тренерами при тренері на курсі -- не входить; минулий; чернетка.
- Лічильники: `cancelled` не рахується; `paid`; очно/онлайн.
- Профіль: збереження; у БД шифротекст; маскування в адмінці без права.
- Пропозиції: створення; надсилання; блокування після надсилання;
  повернення; видалення лише чернетки; чужа -> 404.
- Договір: без файлу -> 404; з файлом -> PDF.
- FAQ: санітизація; підстановка `{email}` і fallback.
- Прив'язка акаунта: унікальність.
- Тести прибирають створених користувачів у teardown.

## 9. Фази комітів (main)

1. Модель і міграція (+ тест оборотності міграції).
2. Сервіс кабінету.
3. Кабінет: блюпринт, шаблони, CSS/JS, навігація.
4. Адмінка і налаштування «Для тренерів».
5. Сповіщення.
6. Документація: README, перелік маршрутів, каталоги перекладу.

## Уточнення під час планування та реалізації

1. PDF договору зберігається в БД: `site_settings.trainer_contract_pdf` --
   deferred `LargeBinary`, а не `MediaFile`, тому що `/media/` публічний.
2. Дефолтний FAQ живе в коді (`app/data/trainer_faq.py`). Порожній
   `trainer_faq_html` означає дефолт. Збереження незміненого дефолту
   зберігає `''` після нормалізації переносів рядків.
3. Анкета в адмінці -- окрема сторінка, `/admin/trainers/<id>/questionnaire`,
   під `trainers.view`. Реквізити показуються лише з `trainers.manage`.
4. «Для тренерів» -- окрема сторінка налаштувань, `/admin/settings/trainers`,
   під `settings.manage`.
5. Фото в анкеті -- `MediaFile` з `entity_type='trainer_profile'`.
6. Редактор FAQ -- звичайна HTML-textarea, санітизована `sanitize_rich_text`.

## Поза обсягом

- Синхронізація анкети з публічною карткою тренера.
- Список учасників для тренера.
- Листи тренеру про зміну статусу пропозиції.
- Самостійна реєстрація в ролі тренера (прив'язку робить лише адмін).
- PDF договору (надасть замовник; до того -- заглушка).
