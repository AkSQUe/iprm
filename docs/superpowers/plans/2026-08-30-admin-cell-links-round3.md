# План: перелінковка комірок, третя черга

## Контекст

Дві черги позаду (`29dfd72`, `51bcbdc`, `9dad395`). Лишились реєстри, де
фільтр або сторінка вже є, а комірка мовчить.

## Принцип (той самий)

1. Сутність веде у свою картку; число -- у перелік, який це число дає;
   технічне значення діагностичного реєстру -- у той самий реєстр, звужений
   за цим значенням.
2. Нуль і прочерк не клікаються.
3. Дві комірки одного рядка не ведуть в одне й те саме місце.
4. Посилання не успадковує поточний зріз, але мусить нейтралізувати
   ненейтральний дефолт цілі.
5. Значення береться з ПОЛЯ МОДЕЛІ, яке приймає фільтр, а не з лейбла. Якщо
   колонка показує один вимір, а фільтр звужує за іншим -- посилання не
   робиться, хоч би як схоже вони називались.

## Global Constraints

- CSS не додавати й не міняти. Ніяких inline-стилів, скриптів, емодзі.
  Коментарі українською: ЧОМУ, у тоні сусіднього коду. Коментар не має
  обґрунтовувати сценарій, якого схема не допускає.
- Роути, моделі, запити НЕ чіпати. Якщо для лінка бракує фільтра -- лінк не
  робиться, це йде у звіт.
- НЕ комітити.
- Кожне посилання дістає сторож, що перевіряє САМЕ тег навколо значення.
  Зразок: `tests/test_routes/test_admin_deadend_links.py`.
- Тест, що створює користувачів, прибирає їх за собою.
- У дереві паралельно працює інший напрям. Чіпати тільки свої файли.

## Задача 1: реєстри, де значення веде у власний фільтр

Файли: `app/templates/admin/blog_comments.html`, `meta_lead_events.html`,
`meta_lead_detail.html`, `online_courses.html`, `materials_overview.html`,
новий тест `tests/test_routes/test_admin_registry_filter_links.py`.

1. `blog_comments.html` -- ПІБ автора веде в `users(q=c.email)`, і лише коли
   `c.email` заповнений (модель це допускає); email під ним лишається
   текстом, щоб не було двох посилань в одну ціль. Бейдж статусу веде в
   `blog_comments(status=c.status)` -- поле, не `status_label`. Допис у
   сусідній комірці вже злінкований, не чіпати.
2. `meta_lead_events.html` -- бейдж статусу -> `meta_lead_events(status=event.status)`,
   джерело -> `meta_lead_events(source=event.source)`. Обидва фільтри є
   (`app/admin/routes_meta_leads.py:776-777`). Колонку з `lead_id` не
   чіпати: вона вже веде в картку ліда.
3. `meta_lead_detail.html`, таблиця подій ліда -- ті самі два значення
   ведуть у РЕЄСТР подій із тим самим фільтром
   (`admin.meta_lead_events`), бо власного фільтра ця сторінка не має.
4. `online_courses.html` -- УВАГА, пастка: колонка статусу показує
   ВІДДАЛЕНИЙ стан Sintegrum (`remote_status_label`), а фільтр `status`
   звужує за ЛОКАЛЬНИМ станом публікації й готовності
   (`published/hidden/ready/incomplete/vanished`,
   `app/admin/routes_online_courses.py:34-40,57-70`). Тому:
   - лінкується лише гілка `{% if c.is_vanished %}` («Зник») ->
     `online_courses_list(status='vanished')`;
   - у колонці «Готовність» «Готовий» -> `status='ready'`, «Бракує даних»
     -> `status='incomplete'`;
   - решта гілок статусу лишається текстом, і коментар мусить пояснити
     ЧОМУ (два різні виміри), інакше наступний додасть лінк, що бреше.
5. `materials_overview.html:140` -- бейдж статусу ->
   `materials_overview(status=r.status)` (фільтр порівнює саме
   `MaterialReservation.status`, `routes_materials.py:788-789`). Кількість
   позицій (`r.items|length`) НЕ чіпати: рядок уже двічі веде в
   `instance_materials`, третій лінк в ту саму ціль порушує принцип 3.

## Задача 2: люди й тарифи

Файли: `app/templates/admin/refund_form.html`, `course_tariffs.html`,
`instance_tariffs.html`, новий тест
`tests/test_routes/test_admin_refund_and_tariff_links.py`.

1. `refund_form.html:65` -- ПІБ покупця веде в
   `user_detail(user_id=order.user.id)`. Email у тій самій комірці лишається
   текстом. Сторінка повернення зараз не має жодного входу в картку людини,
   хоч рішення про повернення ухвалюють саме по людині.
2. `course_tariffs.html` і `instance_tariffs.html` -- назва тарифу веде в
   його редактор (`course_tariff_edit` / `instance_tariff_edit`); узяти той
   самий виклик, що вже стоїть у кнопці дії цього рядка, з тими самими
   аргументами. Решту комірок (порядок, ціна, формат, склад) не чіпати.
