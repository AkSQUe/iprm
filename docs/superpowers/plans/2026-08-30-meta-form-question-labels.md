# Справжні підписи питань і відповідей Meta-форми

**Дата:** 30.08.2026
**Симптом:** на картці ліда (`/admin/meta-leads/<id>`) питання й відповіді
показані як `ваша_спеціальність?` / `ортопедія_/_травматологія` -- нижній
регістр, пробіли замінені підкресленнями.

## Діагноз

Це не наша обробка. `field_data` з Graph API для питань із варіантами
відповіді містить не текст варіанта, а його внутрішній КЛЮЧ; так само
слугіфіковані назви питань. Вільний текст (ПІБ, email) приходить як є --
саме тому на скріншоті він з пробілами й великими літерами.

У `app/` немає жодного `replace(' ', '_')`: `flatten_field_data`
(`meta_lead_ingest.py`) кладе значення дослівно, `_custom_answers`
(`routes_meta_leads.py`) і шаблон лише показують.

Людські підписи Meta віддає окремо -- у схемі самої форми:

```
GET /{form_id}?fields=questions{key,label,type,options{key,value}}
```

де `label` -- текст питання, а `options[].value` -- текст варіанта під
ключем `options[].key`.

## Рішення

Тягнути схему форми і підставляти підписи НА ПОКАЗІ. `field_data`
лишається дослівним: контракт колонки -- «усі відповіді як їх віддала
Meta», і схема, що приїхала пізніше, має полагодити вже наявні картки, а
не лише майбутні.

### Кроки

1. **Контракт** (`meta_contracts.py`): `FORM_FIELDS` -- перелік полів
   форми, поряд із `LEAD_FIELDS`. Одне джерело для клієнта і для фейка.
2. **Клієнт** (`meta_graph_client.py`): `get_form(form_id)`;
   `list_page_forms` просить `FORM_FIELDS` -- питання приїжджають тим
   самим запитом, без зайвої квоти.
3. **Модель** `MetaLeadForm` (`meta_lead.py`) + міграція: `form_id`
   унікальний, `questions` JSON у вигляді
   `{ключ: {label, options: {ключ: підпис}}}`, `synced_at`.
4. **Сервіс** `meta_form_schema.py`: розбір відповіді Graph API у цю
   форму, upsert, підстановка підписів у відповіді ліда і запасний
   `humanize` для форм, схеми яких немає (видалена форма, старий лід).
5. **Наповнення**: звірка (`reconcile`) оновлює схеми всіх активних форм
   Сторінки; воркер після розбору ліда добирає схему його форми, якщо її
   ще немає; кнопка «Оновити підписи форм» у налаштуваннях -- для
   негайного бекфілу.
6. **Показ**: `_custom_answers` віддає вже підписані пари.

### Межі

* Значення в базі НЕ переписуються -- жодного апдейту `field_data`.
* Схеми не звіряються постійно: у Meta опубліковану форму не редагують
  (її дублюють), тож тягнемо, коли немає, і оновлюємо на звірці.
* Експорт реєстру кастомних відповідей не містить -- не чіпаємо.

## Деплой

Міграція `meta_form_schema_20260830` (нова таблиця `meta_lead_forms`),
після неї -- кнопка «Оновити підписи форм» один раз, щоб підписи з'явились
на вже наявних лідах.
