# Промокоди

Знижка або безкоштовна участь за кодом, який людина вводить на формі
реєстрації. Керування -- `/admin/promo-codes`.

## Навіщо

| Сценарій | Налаштування коду |
|----------|-------------------|
| "Забутий" клієнт: дати доступ і свіжий сертифікат | 100%, `max_uses=1` |
| Тренер просить знижку колезі | 20-50%, `max_uses=1` |
| Перевірка механіки реєстрації та автолистів | 100%, без ліміту, вимкнути після тесту |
| B2B-фарма: запросити N лікарів за рекламний внесок | пакет із N кодів (поле "Скільки кодів створити"), прив'язка до проведення |
| Комплексна пропозиція клініці (пробірки 60+ тис) | 100%, `max_uses=1-2`, прив'язка до курсу |

## Модель

- **`promo_codes`** -- сам код. `code` зберігає написання для показу,
  `code_norm` (casefold без пробілів) -- ключ пошуку й унікальності, тож
  `Дмитро`, `дмитро` і `ДМИТРО` -- один і той самий код.
- **`promo_redemptions`** -- реєстр застосувань: одне активне списання на
  реєстрацію (partial-unique index `WHERE status = 'applied'`), анульовані
  рядки лишаються в історії. Це джерело правди; `promo_codes.used_count` --
  денормалізація для швидких перевірок (кнопка "Перерахувати" на картці
  коду зводить її з реєстром).
- **`event_registrations.promo_code_id` / `discount_amount`** -- знімок на
  реєстрації. `payment_amount` уже містить суму ПІСЛЯ знижки;
  `reg.amount_before_discount` повертає суму до неї.

## Параметри коду

| Поле | Значення |
|------|----------|
| Тип знижки | `percent` (1-100) або `amount` (грн) |
| Ліміт застосувань | `max_uses`; порожнє -- без обмежень |
| Ліміт на людину | `per_user_limit`, за замовчуванням 1; порожнє -- без обмежень |
| Скільки кодів створити | `batch_count` > 1 -- поле "Промокод" стає префіксом, кожен код отримує власний суфікс (PHARMA-A7K3XY) |
| Термін дії | `valid_from` / `valid_until`; порожні -- безстроково |
| Область дії | усі курси / один курс / одне проведення (проведення вужче й має пріоритет) |
| Активність | вимкнений код не спрацює, історія лишається |

Знижка ніколи не перевищує суму замовлення: і 100%, і "мінус 5000 грн" з
ціни 3000 дають рівно нуль.

## Як це працює

1. Людина вводить код у полі "Промокод" на формі реєстрації. Кнопка
   "Застосувати" перевіряє його запитом на `/registration/instance/<id>/promo-check`
   і одразу перераховує суму. Без JS код просто їде разом із формою --
   сервер перевіряє його на сабміті (progressive enhancement).
2. На сабміті `promo_service.validate` перевіряє код ДО створення
   користувача: помилковий код нічого не залишає по собі.
3. `registration_service.create_or_reactivate` рахує суму зі знижкою, а
   `promo_service.apply_to_registration` пише рядок реєстру і збільшує
   лічильник під `SELECT ... FOR UPDATE` (два одночасні чекаути на код з
   `max_uses=1` не пройдуть обидва).
4. Знижка 100% робить реєстрацію безкоштовною зі звичайними наслідками:
   `status=confirmed`, `payment_status=paid`, одразу видається номер місця.
5. Повернення коштів (`payment_ops`) анулює списання -- місце у ліміті
   звільняється, знімок знижки на реєстрації лишається для звітів.

## В адмінці

- **`/admin/promo-codes`** -- список із пошуком і фільтром, створення,
  вмикання/вимикання, видалення. Видалення коду не чіпає суми на
  реєстраціях (FK `SET NULL`), але прибирає історію його застосувань.
- **Картка коду** -- скільки використано, скільки дійшло до оплати,
  скільки грн віддано знижками, повна історія застосувань із переходом до
  учасника.
- **Форма учасника** (`/admin/registrations/<id>/edit`) -- поле "Промокод"
  застосовує знижку вручну. Там "Сума оплати" -- це сума ДО знижки;
  порожнє поле промокоду знімає раніше застосований код і повертає його
  ліміт. Реєстрацію, за яку гроші вже пройшли онлайн (є `payment_id` і
  статус `paid`), промокодом не чіпаємо: саме за `payment_amount` LiqPay
  робитиме повернення, тож спершу рефанд, потім знижка.
- **Пакет кодів** -- на сторінці створення поле "Скільки кодів створити".
  Коди генеруються з алфавіту без 0/O та 1/I/L (їх диктують телефоном),
  після створення список одразу відфільтровано за префіксом.
- **Список реєстрацій** і xlsx-експорт учасників показують промокод і
  суму знижки. У порожньому шаблоні для імпорту цих колонок немає -- ними
  володіє promo_service, і заповнення їх у файлі нічого б не змінило.
- Застосування та анулювання пишуться в audit-лог
  (`promo_applied` / `promo_voided` / `promo_batch_created`) з актором,
  сумою та кодом.

## Обмеження

- Один промокод на реєстрацію (коди не складаються).
- Реферальні бали й промокоди не пов'язані: це різні механіки, знижка не
  впливає на нарахування реферера (бали рахуються за фактом оплати).
