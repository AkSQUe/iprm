## Етап E. Складні роботи — окремі проходи по фазах

### E1. Тарифна вилка (Блок 2.2) — ПОГОДЖЕНО, великий scope
Ціни кожного тарифу вводяться вручну. Фази:
1. **Модель**: таблиця `instance_tariffs` (instance_id, name, description, price, is_active, sort_order, max_seats?). `effective_price` → мінімальний активний тариф («від N ₴»).
2. **Адмінка**: CRUD тарифів на сторінці редагування проведення (`instance_edit.html`).
3. **Публічна частина**: вибір тарифу на сторінці курсу/реєстрації; ціна в картках — «від N ₴».
4. **Оплата**: `EventRegistration.tariff_id`, сума LiqPay/IBAN з тарифу; звірка оплат.
5. **Пакети/знижки** (ідея Multimed «маршрути −15/−18/−20%») — окреме погодження.

### E2. Структура курсу за новим баченням (Блок 2.1) — деталі бачення в переписці
Фази: 1) зафіксувати нову структуру секцій detail.html; 2) перекомпонувати шаблон. *(Блок 2.5 «схожі курси» вже реалізовано автоматично по тегах — коміт `e587378`; ручний вибір `related_courses` можна додати пізніше за потреби.)*

### E3. Flow реєстрації/оплати (Блок 4.1) — [!] чекає узгодження нового flow
Фази (після погодження): 1) мінімальна форма учасника, решта питань — пізніше; 2) підтвердження email після оплати; 3) звірка «оплата ↔ email» в адмінці (список оплачених без підтвердження); 4) окремий вхід для user vs учасник.

### E4. Фільтри-чіпси спеціальностей (Блок 3.2) — [!] чекає приклад від Дмитра
Референс Multimed: рядок спеціальностей, що біжить + панель фільтрів (напрям/формат/тривалість/бюджет + сортування). Реалізація після прикладу.
